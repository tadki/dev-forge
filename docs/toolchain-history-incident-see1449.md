## 3. 覆盖假设判定

**判定: 脚本自身排除 (证据充分), 具体覆盖动作证据不足; 105 侧过期副本覆盖假说与全部观测相容。**

1. **排除脚本自写**: 淘汰逻辑 (`evict_daily`) 只删最旧 key, 不可能产生「保留 08-29、删除 10-05..10-10」形态;
   写入路径 mktemp + fsync + `os.replace` 原子替换, 排除撕裂写。与 SEE-1448 结论一致。
2. **排除 210 参与**: 210 上无 toolchain-reports, 无副本可考。
3. **过期副本假说相容性**: 若覆盖源是 105 侧一份止于 09-21 的旧 history (105 最后一次正常日检在 09-21),
   则观测形态被完整解释 — ≤09-21 全保留 (含 08-29 旧口径日)、09-22..10-04 无记录 (run failed 未写盘)、
   **10-05..10-10 丢失 (仅存在于 150)**、10-11 起由本机日检重建。覆盖窗与迁移窗 (10-10 计划迁回、
   10-11 免密通道验证并开始执行) 精确吻合。
4. **不可证实部分**: 迁移操作本身不留仓内/daemon 日志, 覆盖瞬间的直接证据 (源文件、执行命令) 不可得。

## 4. 恢复结论: 不可达, 按不可恢复处置

受支持通道探测 (2026-10-22, 全部只读):

| 通道 | 命令 | 结果 |
|---|---|---|
| 105 → 150:2222 | `bash /dev/tcp` 探测 | **No route to host** |
| 105 → 150:22 | `bash /dev/tcp` 探测 | **超时 (包被滤)** |
| 105 → 150 ICMP | `ping -c2 192.168.1.150` | **100% packet loss** |
| 210 → 150:2222 / 150:22 | `ssh 210 -- nc -z -G 3 192.168.1.150 <p>` | **两端口均 FAIL** |
| 210 → 150 ICMP | `ssh 210 -- ping -c2 -t 3` | **100% packet loss** |
| 210 本机副本 | `ssh 210` 查 `~/.multica/toolchain-reports/` | **不存在** |

150 是 10-05..10-10 六天数据的唯一载体, 现从 105、210 两侧均不可达。按任务边界
(不可达即止, 不开通道、不改网络、不改 150 侧文件), **判定 6 天数据不可恢复, 不做回填**。

## 5. 6 天空洞对 G3/G4/G5 的影响与处置

| 检查 | 影响 | 处置 |
|---|---|---|
| G3 日增 | 读 `history["failures"]` (上一轮运行值), 不按日回溯 — 空洞不传导到后续任何一轮比对 | **无需补偿** |
| G4 周累计 | 10-05..10-10 所在周累计偏低 → 漏报方向; G4 已是 info 观测级 (SEE-1440 裁决) | **接受永久空洞**: 伪造/插值数据会污染 2σ 基线, 比保守漏报危害更大 |
| G5 2σ | 序列缺 6 天, 新口径 n 减小但仍满足 n>=5 门槛 (timeout n=8 / error n=6) | **接受**: 剔除旧口径日守卫后基线即为真实新口径分布 |

空洞处置已固化进本 issue 代码交付: G5 旧口径守卫 (确定性排除, 见 `_g_daily_series`) +
history 防单点覆盖 journal (见 `load_history_with_recovery`), 同类整体覆盖事故今后可自愈。
